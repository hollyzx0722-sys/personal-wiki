DeepSeek V4.1 Flash 推理系统

这篇知识页用小白能看懂的方式，解释 DeepSeek V4.1 Flash 怎样把一个大模型变成能同时服务海量用户的低延迟、低成本系统。

人工智能大模型推理系统工程通俗整理
一句话概述
模型能力只是“厨师”，推理系统才是整家“超级餐厅”：它负责分流请求、安排 GPU、复用缓存、自动加机器，让很多人同时使用模型时仍然又快又省。

先记住 3 个核心目标

更大的吞吐
同一时间服务更多用户。
更低的延迟
用户更快看到第一段回答，后续文字也更快生成。
更低的成本
尽量让昂贵的 GPU 一直工作，少重复计算。

一次请求是怎样走完的

1用户发来文字或图片。
2Tokenizer 把文字切成模型能处理的 token。
3系统先检查以前算过的内容有没有缓存。
4Prefill 负责“读懂题目”，处理输入上下文。
5Decode 负责“逐字写答案”，一步步生成 token。
6系统把结果解析成正文、思考内容、工具调用或 JSON，再流式返回。

Prefill 和 Decode：回答分成两段

阶段通俗理解主要影响
Prefill先把用户的问题和历史对话读懂。多久开始说第一句话（TTFT）。
Decode理解后，一个 token 一个 token 地写答案。回答过程中每秒输出多少字（TBT）。

两阶段分开部署，就能分别调机器：Prefill 常用 2～8 张卡；Decode 因为要同时服务大量生成中的请求，可能使用 64～128 张卡。

KVCache：模型的“读书笔记”

如果每轮聊天都从头重读，计算会非常浪费。KVCache 会保存模型已经处理过的中间结果，下一轮直接复用。

缓存像什么保存位置与时间
Block KVCache仓库里的长期资料。放在 3FS 分布式存储中，可保存几天，规模很大。
SWA KVCache桌面上的短期便签。放在机器内存中，通常只复用几分钟；丢了可以重算。

SWA Bounded Replay 的意思是：短期便签丢失时，只重算最近约 128 个 token，不必把整段历史重新计算。

负载均衡：给 GPU 当“分流员”

不能只按请求数量平均分配，因为一个长文本可能比几十个短文本更费计算。系统会综合输入长度、缓存长度、当前请求数和专家热门程度来分配任务。

Prefill 分流
把长短输入分开估算，按预计计算量分配。
Decode 分流
同时平衡请求数量和 KVCache 总长度。
图片分流
把图片交给当前处理图片块最少的卡。
专家分流
热门专家多复制几个副本，定期重新安排到不同 GPU。

其他加速技巧

自动扩缩容
流量大时增加机器，流量小时减少机器；正在处理长请求的机器会先等待并转移任务。
DSpark 投机解码
小模型先猜几个 token，大模型批量检查，猜对的直接采用，减少一步步生成的等待。文章称线上吞吐提升约 6%。
异步调度
GPU 计算当前步骤时，CPU 同时准备下一步，让 GPU 尽量不空等。
结构化输出
把 JSON Schema、正则等规则编译成“护栏”，每一步只允许模型生成合法 token。

官方报告摘要（2026-10-20）

DeepSeek 官方机构号发布《DeepSeek-V4.1-Flash 大规模推理部署实践》，并同步开源推理框架 DeepInfer。框架兼容英伟达与华为昇腾芯片，重点解决大模型如何低延迟、低成本服务海量用户。

1. PD 分离与大 EP 部署

Prefill 和 Decode 分开部署，实际卡数比例接近 1:1。Prefill 按未命中 token 数估算需求，Decode 按正在计算的请求数估算需求。实例下线时保留 1 分钟宽限期，未完成请求和 KVCache 会整体转发到其他实例。系统保留 ready 机器作为扩容库存，配额占用率超过 0.8 时禁止缩容。故障处理依靠“冗余配额 + 请求级重路由”，并可按剩余健康卡重新确定 EP 规模。

2. KVCache 存储

Block KVCache 存放在独立的 3FS 存储集群，约 100 PiB SSD，峰值聚合读带宽 10 TiB/s、写带宽约 850 GiB/s。存储与计算解耦，任意 Prefill 机器都能命中任意前缀。SWA KVCache 放在本机内存，跨机命中通过 400G VLAN 拉取。Agent 流量 TTL 约 3 天，Chatbot 流量 TTL 约 7 天。

3. SWA Bounded Replay

只重算最近 128 个 token，把恢复成本变成与上下文长度、层数基本无关的常数；Decoder 侧因此让总 Prefill 计算量接近减半。

4. DSpark 与异步调度

DSpark 在 base logits 上加入轻量低秩 bias，提高 draft 准确率；Confidence Head 根据 token 接受概率进行变长验证，线上吞吐比固定验证 5 个 token 提升约 6%。异步调度则让 CPU 调度和 GPU 计算重叠，减少 GPU 空等。

商业价值与单位经济

报告公开了少见的单卡经营数据：单一集群吞吐约 155 万亿 Tokens/天；单卡收入约每小时 38 美元（按波谷价格）；平均输入缓存命中率约 96%。这些数字说明，推理系统本身已经成为模型服务的重要竞争力。

成本护城河
同样售卖 Token，专用推理框架通过 PD 分离、KVCache 复用、SWA Bounded Replay 等方式降低单位成本，通用框架部署未必能达到同样的经济性。
低价也能盈利
低价格带来更多请求，高缓存命中率摊薄重复计算成本，再配合高吞吐形成“低价获量—命中率提升—成本下降”的循环。
开源的战略意图
DeepInfer 兼容昇腾，能够把经过大规模验证的推理方案带入国产算力生态，也让 DeepSeek 在“模型—框架—芯片”的中间层争取标准影响力。

一句话判断

这篇报告表面讲工程实践，实质是在说明：DeepSeek 的护城河不仅是模型能力，还包括以合理成本大规模服务用户的推理工程能力。

最终理解

这篇文章的重点不是介绍聊天界面，而是介绍“如何把大模型做成大规模云服务”。DeepSeek 通过拆分 Prefill/Decode、复用 KVCache、均衡 GPU 负载、自动扩缩容、投机解码和异步调度，让同样的硬件服务更多请求。
