模型计费的核心逻辑

一次调用的费用 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价。公式本身很简单，但"思考算输出、多轮重复计输入、缓存命中打折"三个细节，决定了真实成本和直觉算出来的差多远。

一句话概述
计费单位是每次 API 调用（不是每个会话）。模型先把你的文本切成 token，"读取"按输入价、"生成"按输出价分别计费。输出价通常是输入价的 4~5 倍——因为生成是逐 token 自回归的，每出一个字都要完整跑一遍模型，而读取输入可以并行处理。

核心信息

计费单位Token：英文约 0.75 词 = 1 token；中文 1 字 ≈ 0.6~1 token，视 tokenizer 而定
计费粒度每次 API 调用；会话里每发一条消息就是一次独立计费的调用
思考内容推理模型的 thinking token 按输出价计费，即使不展示给你
缓存命中上下文缓存的输入也计费，但按折扣价（约 0.1×~0.5×）
费用 = 输入tokens ÷ 10⁶ × 输入单价 + 输出tokens ÷ 10⁶ × 输出单价

算一个例子

一次对话：输入 1000 token（约 1000~1500 个汉字），模型回答 500 token。按"输入 20→13 元、输出 100→68 元（每百万 token）"的降价口径：

降价前降价后
输入0.001 × 20 = 0.020 元0.001 × 13 = 0.013 元
输出0.0005 × 100 = 0.050 元0.0005 × 68 = 0.034 元
合计0.070 元0.047 元（约降 33%）

四个容易算错的点

① "思考"计入输出，不是免费的读取
推理模型（深度思考模式）内部推理产生的 thinking token 属于模型"生成"的内容，按输出价计费，即使不展示给你。这是推理模型调用比普通对话贵的直接原因。
② 多轮对话会重复计费输入
每次调用都要把之前的对话历史作为输入重新发送——第 10 轮时，前面 9 轮的内容全都按输入价再收一遍，长对话成本累积增长。上下文缓存可以缓解（见下文）。
③ 输出比输入贵 4~5 倍是行业常态
生成是逐 token 自回归的，每个输出 token 都要完整跑一遍模型；读取输入则可以并行处理。例中 13 vs 68，约 5.2 倍。
④ "一次对话"≠"一次会话"
计费单位是每次 API 调用，不是每个会话。会话里每发一条消息就是一次独立的调用、独立计费。

上下文是 KV Cache 吗？——分两层

层面是什么怎么计费
推理层的 KV Cache模型把输入 token 计算成 Key/Value 矩阵存在显存里，避免每生成一个 token 都重算整个前文所有模型推理都有的基础机制，成本已隐含在输出单价里，不单独收费
产品层的"上下文缓存 / Prompt Caching"把你请求之间的公共前缀（同一段 system prompt、同一批文档、多轮历史）在服务端持久保存一段时间（通常 5 分钟到几小时，命中即刷新）面向用户计费的机制：下次请求前缀完全一致就复用 KV Cache、跳过预填充（prefill），按折扣价计

命中缓存也计费，但打折

缓存命中的部分要收费，只是按折扣价。各家差异很大（截至 2026-11，以官方定价页为准）：

厂商命中价格备注
Claude写缓存 1.25×；命中读取 0.1×首次存入比原价贵 25%，之后读取约一折
OpenAI命中自动 0.5×无需配置，自动生效
DeepSeek命中约 0.1×未命中按原价
Gemini命中约 0.25×缓存存储本身按时间另收存储费

为什么打折而不是免费

显存一直在占着
缓存命中的部分虽然不用重算，但 KV Cache 要持续占用显存；读取缓存也有 I/O 和调度开销。
省掉的是最贵的部分
折扣价 ≈ 显存占用 + 读取开销；相比原价省掉的，是重复的预填充计算——那才是 GPU 算力的大头。
实践含义
长对话 / 长 system prompt 场景，缓存能把输入成本降 50%~90%。

省钱的通用模式

不变的内容放前面，易变的放后面
system prompt、参考资料放最前，用户最新消息放最后——让公共前缀尽可能长。
前缀必须完全一致才算命中
system prompt 里哪怕改一个字、历史消息顺序变动，从那之后的部分全部按原价重算。
